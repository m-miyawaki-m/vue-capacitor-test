# テスト方針と業務シナリオの初回レビュー

Claude Code（Herdr `w3:p2`）が要件定義、単体・結合・総合テスト、在庫 PoC 計画を照合した。判定は must 1件、should 2件、nit 2件。必須指摘が解消すれば同意との回答。

| ID | 指摘 |
| --- | --- |
| M1 | AC2 の Vitest＋MSW、AC3 の Store と API 境界、AC4 の Storybook、AC5 の生成確認について、ケースや担当が明記されていない。 |
| S1 | 業務シナリオの期待結果は利用者が画面で観察できる内容とし、クエリの確認はテストケースに置く。 |
| S2 | 総合テストの期待結果に HTTP メソッド・パス・クエリと固定データの表示内容を明記する。 |
| N1 | 業務フローに利用者・目的・開始条件・分岐・完了状態を明記する。 |
| N2 | HTTP 500 と契約不一致を別の結合ケースにし、対応する受入基準を示す。 |

各段階で立証する範囲とケース・コードの作成時点は整合していた。テストの実行はレビュー対象外。
