# Vitest と Storybook のテスト手順への指摘対応

| 指摘 | 対応 |
| --- | --- |
| S1 | PoC の API 境界は成功時に検証済み本文を返し、失敗時は種類を付けた `ApiError` を投げる契約にした。Store の単体テストで同じ形のエラーを返す。 |
| S2 | API 境界の単体観点と、検索キーの正規化の観点を追加した。検索画面と Store で同じ正規化関数を使う。 |
| S3 | Storybook の Vue アプリへの Pinia 登録と `createSpy: fn` の例を追記した。採用バージョンの組み合わせは導入時に検証する。 |
| S4 | `MainLayout` のメイン領域にフォームを置き、フッターのボタンを画面側から渡す構成を記載した。 |
| N1・N2 | 各テストで Pinia を作ることと、再取得失敗時にデータ・取得時刻を保持することをテスト例に反映した。 |
| N3・N4 | Storybook の呼び出し回数と引数を別々に確認する。部品単独の確認と、部品間の連携を確認する資料を分けた。 |
