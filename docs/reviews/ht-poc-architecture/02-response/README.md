# アーキテクチャ図の指摘対応

- M1・S1・S2・N1。画面制御 Store の保存と、レスポンス Store の取得を分離した。HTTP 応答は Fetch クライアントを経由してアプリ側で判定・検証する。通信・HTTP・検証エラーはレスポンス Store に記録し、前回成功データを保持する。
- S3。詳細に使える項目は一覧から再利用する。項目 ID、詳細 API、直接表示時の再取得は後続で決める。一覧復元の画面制御 Store を追記した。
- N2。合格条件と確認方法のページで、クエリと件数、空白入力、空・エラー表示、再生成時の Git 差分を確認項目として示した。
- N3・N4。MSW CLI がワーカーを生成すること、Orval が Faker ファクトリを生成すること、モックのファイル名は生成結果に合わせることを追記した。
