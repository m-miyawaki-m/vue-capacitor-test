# レイアウトとコンポーネント設計

[編集用の画面レイアウト図](ht-screen-layout.drawio)

## MainLayout と画面構成

`MainLayout` はヘッダー、メインコンテンツ、フッターを配置する。各画面がタイトル、戻る操作、フッターのボタンを渡す。業務画面は Vue Router で切り替え、`RouterView` に表示する。

| 画面 | メインコンテンツ | フッターと遷移 |
| --- | --- | --- |
| 業務メニュー | 業務遷移一覧 | 一覧から入庫・在庫管理へ進む |
| 検索・一覧 | 条件ごとのアコーディオンと結果カード | 検索、バーコード・OCR 読み取り、必要に応じて関連業務を横並びにする。結果カードから詳細へ進む |
| 詳細 | 項目名と値の一覧 | 必要に応じて閉じるなどの操作を置く。検索・一覧へ戻ったら条件、結果、スクロール位置を復元する |
| 関連業務一覧 | 遷移候補が多い場合に業務遷移一覧を表示する | 選んだ業務へ進む |
| 読み取り | バーコード・OCR の切り替え、カメラプレビュー、読み取り結果（将来案） | 結果を確定して呼び出し元の入力欄に反映する。キャンセル時は元の入力値を保持する |

## コンポーネントの責務

- 共通コンポーネントはアコーディオン、結果カードの枠、項目名と値の一覧、業務遷移一覧。遷移一覧は業務メニューと関連業務で共用する。
- 業務コンポーネントは検索項目、カードや詳細の表示項目、画面固有の操作と遷移先を決める。
- 読み取り画面は各業務で共用し、結果の反映先は呼び出し元が決める。認識方式とメーカー SDK の方針が決まった段階で画面構成を確定する。初回は疎通確認画面から公式 Camera を呼んで撮影する。実機確認範囲は [要件定義](../01-requirements/ht-design.md) の受入基準に従う。

検索・一覧では、読み込み中、結果なし、通信失敗を表示する。読み取り画面での失敗表示と再操作は、業務画面ごとの設計で具体化する。業務ごとの画面一覧、遷移表、戻り先も対象業務が決まった時点で定義する。

## 画面と操作の決定状況

| 決めること | 状況 | 現時点の内容 | 残っている判断 |
| --- | --- | --- | --- |
| 共通レイアウト | 決定済み | ヘッダー、メイン領域、フッターを持つ `MainLayout` を共用する。 | 実機でボタンの押しやすさと縦幅を確認する。 |
| 検索・一覧 | 方針あり | 条件ごとのアコーディオン、フッター検索ボタン、結果カード。 | 入庫・在庫管理それぞれの条件、初期値、必須項目、カードの表示項目。 |
| メニュー・関連業務・詳細 | 方針あり | メニューから業務へ進み、一覧カードから詳細へ進む。関連業務が多い場合は遷移先一覧を表示する。 | 各業務の画面一覧、遷移先、戻り先、詳細の操作と表示項目。 |
| 一覧の復元 | 決定済み | 詳細から戻る際に検索条件・結果・スクロール位置を復元する。 | 復元の具体的な実装と、再読み込み・直接アクセス時の扱いは詳細設計で決める。 |
| 読み取り画面 | 方針あり | 各業務から共用し、確定値を呼び出し元へ返す。 | 画面遷移かダイアログか、読み取り方式、キャンセル・失敗時の操作。 |
| メッセージ | 方針あり | 読み込み中、結果なし、失敗を画面に表示する。 | 業務ごとの文言、表示位置、再試行や設定への案内。 |
