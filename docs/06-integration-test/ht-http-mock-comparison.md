# 在庫 PoC の HTTP モックとテスト手段の比較

## 結論案

在庫検索 API 1本の PoC は、**単体では Vitest で API 関数を差し替え、通信を含む結合では Vitest と MSW を使う**構成で検証できる。MSW がテストプロセス内で Fetch を捕捉するので、Prism などの独立した HTTP モックサーバーを起動する必要はない。正常2件、空、500、契約に合わない200を固定値で返せるため、今回の確認には Faker の乱数生成も不要とする。

| ツール | 役割 | 今回の使い方 |
| --- | --- | --- |
| Vitest | テストを実行し、関数の戻り値、状態、呼び出しを判定する。依存関数の差し替えもできる。 | Store 単体では API 関数を固定の戻り値やエラーに差し替える。結合では MSW と組み合わせる。 |
| MSW | 開発・テストでリクエストを捕捉して、ハンドラで決めた応答を返す。 | Node.js の Vitest では `setupServer`、Chrome で動くアプリ側では `setupWorker` を使う。Playwright はそのアプリを操作する。 |
| Faker | ダミーデータを生成する。HTTP リクエストの捕捉・応答はハンドラ等が担当する。 | 今回は手書きの固定データでケースを再現する。多様な入力値が必要になったときに検討する。 |
| Prism | OpenAPI から他のプロセスやツールも接続できる HTTP モックサーバーを起動する。 | 独立した接続先や、Prism によるリクエストの検証が必要になったときに検討する。 |

[Vitest のモック](https://vitest.dev/guide/mocking.html) · [MSW の Node.js 連携](https://mswjs.io/guides/integrations/node) · [Faker のガイド](https://fakerjs.dev/guide/) · [Prism の公式リポジトリ](https://github.com/stoplightio/prism)

## 何を立証できるか

| テスト | 実物を使う範囲 | 確認すること |
| --- | --- | --- |
| Store 単体 | Pinia の Store。API 境界の呼び出しを Vitest で差し替える。 | キーごとの保存、失敗時の前回結果の保持。同時取得時の更新順序。 |
| API 境界の単体 | HTTP の判定・Zod 検証。生成クライアントを Vitest で差し替える。 | HTTP 500 と、200 でも本文の型が違う場合を区別する。 |
| 通信を含む結合 | Vue の画面、Pinia、Orval の Fetch クライアント、Zod。Fetch の応答を MSW が差し替える。 | GET のメソッド・パス・クエリ、正常・空・500・不正本文に応じた Store 更新と表示。要求に一致するハンドラがなければ失敗させる。 |
| ブラウザのシナリオ | Chrome 上でアプリを起動し、ブラウザ版 MSW で固定応答を返す。 | 業務メニューから検索し、対応する GET が1回発生して結果カードが2件表示される。 |

MSW の `setupServer`（`msw/node`）は Vitest のテストプロセス内で Fetch を捕捉する。ポートを公開する独立サーバーの準備は不要。実 API の実装、HTTP サーバーとの接続、認証・CORS、Android からの到達は別途確認する。OpenAPI のリクエスト制約の確認は MSW が自動で行うわけではないため、今回のメソッド・パス・クエリはテストの期待値として明記する。レスポンス本文はアプリの Zod 検証を通す。

## PoC の変更案

- Orval で Fetch クライアント・型・Zod スキーマを生成する。モックは手書きの MSW ハンドラ1本と固定データから始める。
- 基本ハンドラは正常2件を返す。Vitest のケース内で `server.use()` を使って空・500・不正な200へ切り替え、各ケースの後に `resetHandlers()` する。開発時と E2E はブラウザ版の基本ハンドラを使う。
- 正常・空の固定データは Orval が生成した型でチェックし、生成した Zod スキーマで検証するテストに含める。不正な本文は契約違反を再現する専用データとする。MSW のパスと生成クライアントの実リクエストが一致することを、結合テストで確認する。
- 採用を決めたら、PoC 計画のモック設定を `VITE_API_MOCK=msw|off` に揃え、Playwright の `webServer` は `msw` モードで起動する。Orval 設定からモック生成を外し、API 生成手順、結合テストの import、draw.io、資料インデックスを更新する。
- AC1〜AC5 の確認内容は維持する。AC1 の起動モードと AC5 の再生成対象を更新する。AC4 は引き続き固定 props を使う。

本資料は構成の比較と変更案。現行 PoC の変更と実走は採用決定後に行う。
